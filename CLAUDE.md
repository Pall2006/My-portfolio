# Портфолио Павла Мартьянова

Одностраничный сайт-портфолио, опубликован на https://pall2006.github.io/My-portfolio/. Владелец — русскоязычный, не программист: объяснять пошагово и простыми словами, отвечать по-русски.

## Файлы

Каждый файл отвечает за одно. Сборки нет, библиотек нет, только шрифт Manrope из Google Fonts; браузер сам подгружает файлы по `<link>` и `<script>` из `index.html`.

- `index.html` — только разметка и тексты страницы. Без `<style>` и встроенных скриптов: новые стили и код класть в файлы ниже.
- `css/` — стили, по файлу на блок, подключаются в таком порядке:
  - `base.css` — цвета (переменные в `:root`, тёмная тема; `--error` — цвет надписи об ошибке), шрифт, отступы, `h2`, `.eyebrow`, кнопки `.btn`
  - `nav.css`, `hero.css`, `about.css`, `projects.css`, `contact.css`, `footer.css` — по одному на блок страницы; правила для телефона (`@media`) лежат в конце файла своего блока
  - `reveal.css` — анимация появления; **подключается последним**, её `transform` и `transition` перекрывают стили блоков. Поэтому эффекты при наведении на элементы с `.reveal` делать не через `transform`, а через отдельные свойства (`translate`, `scale`) — как подъём карточек в `projects.css`
- `js/` — скрипты: `year.js` (год в подвале), `contact-form.js` (форма → письмо через Web3Forms → «Спасибо!» или надпись об ошибке; ключ доступа в константе `CONTACT_KEY`), `reveal.js` (ставит `.visible` при прокрутке). Обычные скрипты, общая глобальная область — не заводить одинаковых имён переменных в разных файлах.
- `images/photo.jpg` — фото владельца для шапки.
- `start-site.bat` — запуск сайта у себя с автообновлением (см. ниже).
- `docs/` — спецификации функций, согласованные с владельцем, и планы их реализации: `contact-form-spec.md` и `contact-form-plan.md` (форма обратной связи → письмо на почту).
- `tests/` — автотесты (`contact-form.test.js`: форма в jsdom, `fetch` подменён, писем не шлёт). `package.json` нужен только для них: запуск `npm test` (встроенный в Node `node --test`), из зависимостей только jsdom для разработки; на сам сайт не влияет.
- `.gitignore`

## Блоки страницы (сверху вниз)

1. **Меню** (`<nav>`) — липкое, логотип «Павел.» и ссылки на разделы.
2. **Шапка** (`.hero`, `#top`) — «Павел Мартьянов», короткое описание, кнопки «Мои проекты» / «Написать мне», фото справа (на телефоне — над текстом).
3. **Обо мне** (`#about`) — два абзаца и три цифры-факта.
4. **Проекты** (`#projects`) — три карточки (`.card`) с цветной обложкой, названием, описанием, тегами.
5. **Контакты** (`#contact`) — форма: имя, email, сообщение. Сообщения приходят письмом на pall2006@bk.ru через Web3Forms (ключ — `CONTACT_KEY` в `js/contact-form.js`, форма в кабинете Web3Forms называется «Портфолио», адрес сайта там указан `pall2006.github.io`). Во время отправки кнопка «Отправляем…», при успехе — «Спасибо!» (класс `.sent` на `#contact-box`), при сбое или 15 с без ответа — красная надпись `#contact-error`. Подробности — `docs/contact-form-spec.md`.
6. **Подвал** — © год + имя.

## Оформление

Цвета заданы переменными в `:root` в `css/base.css` (акцент — терракотовый `--accent`), есть тёмная тема через `prefers-color-scheme`. Вёрстка адаптивная: точки перелома 860px и 420px. Блоки с классом `.reveal` плавно появляются при прокрутке.

## Разработка по TDD

Вся разработка ведётся по TDD — это правило владельца, без его разрешения не пропускать.

1. При добавлении новой фичи или изменении существующей сначала напиши тесты (в `tests/`), запусти `npm test` и убедись, что они падают, причём по нужной причине — из-за отсутствия фичи, а не из-за ошибки в самом тесте.
2. Только потом пиши код.
3. После написания кода запускай `npm test` и исправляй, если что-то не прошло. Чинить код, а не подгонять тесты.
4. Перед коммитом все тесты должны проходить — запускать весь набор, а не только новые.

## Web3Forms (почта для формы)

- Кабинет: https://app.web3forms.com, вход по почте pall2006@bk.ru (без пароля, ссылкой из письма). Там форма «Портфолио» с ключом из `CONTACT_KEY`, в её настройках адрес сайта `pall2006.github.io` (если сайт переедет на другой адрес — поменять там же). Отправка работает и с localhost, и с опубликованного сайта.
- На входе в кабинет стоит проверка Cloudflare «вы не бот» — Claude её не проходит, в кабинет заходит владелец в своём браузере.
- Ключ не секретный (только шлёт письма владельцу), его можно хранить в коде и присылать в чат.
- Проверять форму без лишних писем: в консоли подменить `window.fetch` на нужный ответ (`{success:true}`, отказ, 500, зависание) или подставить в тело запроса неверный ключ — сервис ответит 400 `success:false`, письмо не уйдёт. Настоящее тестовое письмо слать, только когда владелец готов проверить почту.
