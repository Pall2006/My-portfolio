# Форма обратной связи: план реализации

> **Для исполнителя:** выполнять по задачам через superpowers:subagent-driven-development или superpowers:executing-plans. Шаги отмечены чекбоксами (`- [ ]`).

**Цель:** форма в `#contact` отправляет сообщение письмом на pall2006@bk.ru через Web3Forms. Посетитель видит состояния «Отправляем…», «Спасибо!» или надпись об ошибке.

**Архитектура:** статическая страница без сборки. `js/contact-form.js` отправляет поля формы через `fetch` в API Web3Forms и переключает состояния. Разметка надписи об ошибке лежит в `index.html`, её вид задан в `css/contact.css`, цвет в `css/base.css`.

**Технологии:** чистые HTML, CSS и JS (обычный `<script>`, без модулей), Web3Forms API.

**Спецификация:** `docs/contact-form-spec.md`.

## Общие ограничения

- Адрес получателя: pall2006@bk.ru. На странице он **не показывается**.
- Тема письма: `Новое сообщение с сайта-портфолио`.
- Текст на кнопке во время отправки: `Отправляем…` (символ многоточия «…», не три точки). В обычном состоянии: `Отправить`.
- Текст ошибки: `Не удалось отправить. Попробуйте ещё раз чуть позже.`
- API: `POST https://api.web3forms.com/submit`, JSON с полями `access_key`, `subject`, `name`, `email`, `message`. Успех — HTTP 2xx и `success === true` в ответе.
- Без библиотек и сборки. В `index.html` нет `<style>` и встроенных скриптов (правило из `CLAUDE.md`).
- Скрипты делят одну глобальную область. Новые глобальные имена начинаются с `contact`. Уже заняты `box` и `form` (в `contact-form.js`).
- Тестов-фреймворка в проекте нет. Проверка идёт во встроенном браузере на http://localhost:5180 (конфигурация `portfolio` в `C:\Users\Павел\Desktop\test\.claude\launch.json`).
- Автор коммитов: `Павел Мартьянов`.

## На что смотреть при проверке

1. **Сервис завис и не отвечает.** Без ограничения времени кнопка навсегда останется в состоянии «Отправляем…». Нужен таймаут 15 секунд (`AbortController`), после него показывается ошибка. Проверка в задаче 2, шаг 5.
2. **Ответ не в формате JSON** (например, HTML-страница с ошибкой 500). Это должно считаться ошибкой, а не ломать скрипт. Проверка в задаче 2, шаг 5.
3. **Двойной клик по «Отправить».** Должен уйти ровно один запрос. Проверка в задаче 2, шаг 4.
4. **Надпись об ошибке в тёмной теме** должна быть читаемой на фоне `--surface`. Проверка в задаче 1, шаг 3.
5. **Ошибка → «Написать ещё».** После успешной повторной отправки и возврата к форме старой надписи об ошибке не видно. Проверка в задаче 2, шаг 6.
